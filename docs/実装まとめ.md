# 往還 実装まとめ

設計書「往還 — 問いに答えるだけで回るタスク・アイデア管理ツール 設計書」(第2版, 2026-11-10)をもとに作った実装の現状と、設計書から変えた点・決めた点をまとめる。設計書そのものは作者の手元にある。

最終更新: 2026-11-12

## 構成

| 層 | 中身 |
| --- | --- |
| 画面 | Next.js (App Router) の1ページ `src/app/page.tsx`。左=時間軸、右=文脈 |
| API | `src/app/api/*`(Route Handlers)。画面からは fetch で呼ぶ |
| ロジック | `src/lib/posts.ts`(投稿・木・ルーチン)、`src/lib/questions.ts`(問いの規則エンジン)、`src/lib/parse.ts`(日付・見積もりの読み取り)、`src/lib/backup.ts`(書き出し・復元) |
| データ | SQLite `data/reflow.db`(gitignore対象)。表は `posts` / `routines` / `daily_state` / `question_log` と全文検索用の `posts_fts` |

AIは使わない。つなぐ先の候補は最近触った順、問いと戻りはすべて規則で決める。

開発用のサンプルデータは `npm run seed` で入る(既存データは消える)。

## 問いの出し方(実装している規則)

優先順位は上から。いま線の上に先頭の1つだけを出し、「あとN問」を添える。

1. 書いた直後: 「これは〇〇の続き?」(つなげる木があるときだけ)、「いつやる?」
2. 朝: 持ち越しの「今日やる?」、続いて「今日の約束、この順でいい?」。**両方合わせて1日5問まで**
3. 確かめる日: 「効いた?」(**1つずつ**。答えると次が出る)
4. 止まった枝: 「どうなった?」(1日1件)
5. 過去の戻り: 「今はどう思う?」(1日3件)
6. いつか: 「まだやりたい?」(**1つずつ**)

- 書いている最中は問いのカードを畳み、「問いは書き終えたら戻ります」と出す。
- 長く開かなかった後も、上の上限と「1つずつ」のおかげで問いは溜まらない。

## 画面

### 左: 時間軸

上から、過去—記録(既定で畳む。開くとスクロールでさかのぼれる)→ 問いのカード → いま線 → 入力欄 → いま線に溜まった持ち越し → 今日この後(予測の時間帯・終了予定)→ 明日 → いつでも(いつか・戻ってくるもの)。

カードは押すと選ばれ、選んだカードだけに操作が出る。

| カード | 出る操作 |
| --- | --- |
| 記録 | つなぐ/つなぎ直す、編集、未来へ置く(約束にする)、削除 |
| 約束 | (今日なら)始める/終える、日付を変える(今日/明日/日付/いつか)、つなぐ/つなぎ直す、編集、記録にする、削除 |
| 済み | つなぐ/つなぎ直す、編集、削除 |

Esc で選択を外す。

### 右: 文脈

左の状態に応じて自動で切り替わる。上にあるものほど優先する。

| 左の状態 | 右に出るもの |
| --- | --- |
| 書いている | つなぐ先を選ぶ(入力中は他の理由で右を動かさない) |
| 「つなぐ/つなぎ直す」を押した | そのカードのつなぐ先を選ぶ |
| 木にあるカードを選んだ | 木の中のその位置(青枠)と「つなぎ直す」 |
| 木にないカードを選んだ | そのままつなぐ先を選べる(約束は「つながなくても大丈夫」と添える) |
| 書き終えた直後 | いま書いた投稿の位置 |
| 約束を実行中 | その約束の「なぜ」(つながっている木) |
| 朝の問い(持ち越し・順番) | 今日の予定の時間帯、合計、終了予定、持ち越し |
| 効いた? | 決めたこと、そこから生まれた約束(状態・予定日・見積もりと実績・超過)、その下に木 |
| 続き?/今はどう思う?/どうなった? | その問いの木(対象を青枠) |
| どれでもない | 森 |

右上の「森」で、どの文脈からも抜けられる。

### つなぐ先の選び方(TreePicker)

- 最近触った木3つを、最新の先端の冒頭と一緒に上に出す。押すと「最新の先端の続き(弟)」につなぐ(設計書の既定位置)。
- 検索欄で、木の名前だけでなく中身からも探せる。当たった投稿の冒頭も出る。
- 「開く ›」で木の中に入り、任意のカードの「この下に」で子としてつなげる。
- 入力欄の「⠿ 右へドラッグ」をつかんで右に落としてもよい。森の一覧の木に落とすと最新の先端の続き、開いた木のカードの上に落とすと子(深める)、カードの間に落とすと弟(続ける)。落とすのはつなぐ先を決めるだけで、投稿は「記録する」「未来へ置く」で確定する。
- つなぎ直すときは、木を押してもすぐには確定せず、開いて位置を確かめてから選ぶ。木から外して新しい木にすることもできる。

## 設計書から変えた点・決めた点

| 項目 | 設計書 | 実装 | 理由 |
| --- | --- | --- | --- |
| 利用者の動詞 | 書く・答える・やるの3つだけ | 選んだカードに、編集・削除・記録⇄約束・日付を変える・木につなぐを追加 | 作者の判断(2026-11-12)。書いた後の直しが問いだけでは足りなかった |
| 右でできる操作 | ドラッグでつなぐ位置を直すだけ | 加えて、つなぐ先の選択(検索・この下に) | 書きながら木を選ぶ操作を、入力欄のボタンから右の一覧へ移したため |
| 書きながら木を選ぶ | 最近触った木を3つ、残りは名前で探す | 3つ+名前と中身で検索+位置を直接指定 | 後からドラッグで直す手間を減らす |
| 森の根 | (定めなし) | 親のない記録。済みの約束は、考えがつながっているときだけ根にする | 頼まれ仕事を終えたものが木として並び、「続き?」の候補になっていたため |
| 「違う」と答えたとき | 未決 | 最近触った次の木を出す。候補が尽きたら新しい根 | 仮置き |
| 確かめる日 | 未決(一律2週間か、約束の終了日からか) | 一律2週間後 | 仮置き |
| 測り方 | 画面に出さず、書き出したデータから数える | `question_log` に問いの表示・回答・あとでを1日1回ずつ記録し、書き出しに含める | 「問いに答えた割合」を数えられるようにするため。開いた日は `daily_state` の行で分かる |

## データと書き出し

- 投稿(`posts`)が中心。状態は 記録 / 約束 / 済み / 手放した。親は1つだけ(任意)。
- JSON書き出し(version 2)は `{ version, exported_at, posts, routines, daily_state, question_log }`。
- 復元は、この形式と古い形式(投稿の配列)の両方を受ける。含まれている表だけを置き換える。古い書き出しで欠けている列は既定値で埋める。
- Markdown書き出しは投稿の一覧とルーチン。
